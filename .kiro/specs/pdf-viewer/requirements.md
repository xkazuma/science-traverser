# Requirements Document

## Project Description (Input)

**誰の課題か**: 機密性の高い PDF を外部にアップロードせず閲覧したいユーザー、および将来的に
文書へ注釈やレイアウト解析を施したいユーザー。

**現状**: 本リポジトリにはアプリケーションコードが存在せず、PDF を閲覧する手段がない。

**何を変えるか（フェーズ1）**: Vue 3 + Vite + TypeScript + Pinia と raw `pdfjs-dist` を用いて、
クライアントサイドで完結する PDF ビューアを構築する。ローカル PDF をファイル選択／ドラッグ&ドロップ
で開き、連続スクロールで描画する。ページ送り・ズーム・フィット、選択可能なテキスト層、
アウトライン／サムネイルによるナビゲーション、大規模 PDF 向けの仮想化、ローディング／エラー状態を
提供する。各ページにはキャンバス層・テキスト層に加えて、PDF ビューポート座標で位置決めされる
**オーバーレイ層**（フェーズ1では空だが配線済み）を常設する。

**スコープ外（将来構想・本spec では実装しない）**: マーカ／ハイライト・メモの保存、レイアウト解析
（docling / paddleocr 相当）による領域検出と描画、レイアウトのグラフ構造管理。ただしフェーズ1の
アーキテクチャはこれらを阻害してはならない（オーバーレイ層・PDF単位座標・予約ストアスライスが
拡張点となる）。

## Introduction

本要件は、クライアントサイドで完結する PDF ビューア（フェーズ1）が満たすべきユーザー観測可能な
振る舞いを定義する。すべての受け入れ基準の主語は「PDF ビューア」とする。技術選定や内部構造は
設計フェーズ（design.md）で扱い、本書では扱わない。

## Boundary Context

- **In scope**: ローカル PDF を開く（選択／ドラッグ&ドロップ）、連続スクロール描画、ページ
  ナビゲーション、ズーム／フィット、テキスト選択、アウトライン／サムネイルナビゲーション、
  大規模 PDF の仮想化、ローディング／エラー状態、ズーム間でのレイヤ整合（オーバーレイ拡張点の
  座標基盤を含む）。
- **Out of scope**: マーカ／メモの保存・永続化、レイアウト解析（領域検出・OCR）、レイアウトの
  グラフ構造管理、サーバー連携・クラウド保存、PDF の編集・書き出し。
- **Adjacent expectations**: フェーズ1のビューアは将来の注釈・領域表示機能が接続する拡張点
  （空のオーバーレイ層と安定した座標基盤）を提供するが、注釈データ自体は所有・実装しない。

## Requirements

### Requirement 1: PDF ファイルを開く

**Objective:** As a 閲覧者, I want ローカルの PDF をファイル選択またはドラッグ&ドロップで開きたい, so that 外部にアップロードせずに文書を表示できる

#### Acceptance Criteria
1. When ユーザーがファイル選択 UI から PDF ファイルを選択する, the PDF ビューア shall その PDF の読み込みを開始する。
2. When ユーザーがアプリ画面上に PDF ファイルをドラッグ&ドロップする, the PDF ビューア shall その PDF の読み込みを開始する。
3. While ユーザーがファイルをドラッグ中である, the PDF ビューア shall ドロップ可能であることを示す視覚的フィードバックを表示する。
4. If 選択またはドロップされたファイルが PDF 形式でない, then the PDF ビューア shall 読み込みを行わず、形式が不正である旨のエラーメッセージを表示する。
5. The PDF ビューア shall PDF ファイルの内容を外部サーバーへ送信せず、クライアント内のみで処理する。

### Requirement 2: PDF ページの描画

**Objective:** As a 閲覧者, I want 開いた PDF の全ページを鮮明に表示してほしい, so that 文書の内容を読める

#### Acceptance Criteria
1. When PDF の読み込みが正常に完了する, the PDF ビューア shall ページを縦方向の連続スクロールで表示する。
2. The PDF ビューア shall 各ページを、表示中のデバイスピクセル比に応じて鮮明に（ぼやけなく）描画する。
3. While ページが画面に表示されている, the PDF ビューア shall そのページのテキストを選択・コピー可能な状態で重ねて表示する。
4. The PDF ビューア shall すべてのズーム倍率において、テキスト層・オーバーレイ層をページ画像と位置整合した状態で表示する。
5. While ページ幅が表示領域の幅より狭い, the PDF ビューア shall そのページを表示領域内で水平方向に中央揃えで配置し、左右の余白を均等にする。

### Requirement 3: ページナビゲーション

**Objective:** As a 閲覧者, I want 現在ページの把握と任意ページへの移動をしたい, so that 大きな文書内を効率よく移動できる

#### Acceptance Criteria
1. The PDF ビューア shall 現在表示中のページ番号と総ページ数を表示する。
2. While ユーザーがスクロールしている, the PDF ビューア shall 表示領域に応じて現在ページ番号の表示を更新する。
3. When ユーザーが「次ページ」または「前ページ」操作を行う, the PDF ビューア shall 対応するページが表示される位置へ移動する。
4. When ユーザーが特定のページ番号を指定して移動を要求する, the PDF ビューア shall そのページが表示される位置へ移動する。
5. If 指定されたページ番号が有効範囲外である, then the PDF ビューア shall 移動を行わず、現在の表示を維持する。
6. While いずれの PDF も読み込まれていない, the PDF ビューア shall ページ表示を「0 / 0」とする。

### Requirement 4: ズームとフィット

**Objective:** As a 閲覧者, I want 表示倍率を変更し、画面幅やページ全体に合わせたい, so that 読みやすいサイズで閲覧できる

#### Acceptance Criteria
1. When ユーザーが拡大または縮小操作を行う, the PDF ビューア shall 表示倍率を変更し、現在の倍率を再描画する。
2. The PDF ビューア shall 表示倍率を、定義された下限値と上限値の範囲内に制限する。
3. When ユーザーが「幅に合わせる」を選択する, the PDF ビューア shall ページ幅が表示領域の幅に収まる倍率で描画する。
4. When ユーザーが「ページ全体に合わせる」を選択する, the PDF ビューア shall ページ全体が表示領域に収まる倍率で描画する。
5. While フィットモードが有効である, when 表示領域のサイズが変化する, the PDF ビューア shall フィット倍率を再計算して再描画する。
6. While PDF が読み込まれている, when ユーザーがブラウザ標準のズーム操作（Ctrl/⌘ と「＋」「－」キー、または Ctrl/⌘ を押しながらのホイール）を行う, the PDF ビューア shall ブラウザ既定のズームを抑止し、PDF 表示のズームイン／アウトに割り当てる。

### Requirement 5: アウトラインとサムネイルによるナビゲーション

**Objective:** As a 閲覧者, I want 目次（アウトライン）とサムネイルから移動したい, so that 構造的に文書を辿れる

#### Acceptance Criteria
1. Where PDF にアウトライン（しおり）が含まれている, the PDF ビューア shall そのアウトライン項目を一覧表示する。
2. When ユーザーがアウトライン項目を選択する, the PDF ビューア shall 対応する移動先が表示される位置へ移動する。
3. The PDF ビューア shall 各ページのサムネイル一覧を表示する。
4. When ユーザーがサムネイルを選択する, the PDF ビューア shall 対応するページが表示される位置へ移動する。
5. Where PDF にアウトラインが含まれていない, the PDF ビューア shall アウトラインタブを非表示にし、サムネイル一覧のみを表示する。
6. The PDF ビューア shall ナビゲーション領域（アウトライン／サムネイル）と本文表示領域を独立してスクロールできるようにする（一方のスクロールが他方を連動させない）。
7. While あるページが本文に表示されている, the PDF ビューア shall そのページに対応するアウトライン項目を視覚的に強調する。
8. When 強調対象のアウトライン項目がアウトラインの表示領域外にある, the PDF ビューア shall その項目（複数該当時は最後の項目）が表示されるまでアウトライン領域を自動スクロールする（本文表示のスクロールには影響しない）。
9. When PDF 本文が表示された後にアウトライン／サムネイルの準備が完了する, the PDF ビューア shall ナビゲーションドロワーをスライドイン遷移で表示する（PDF 本文の描画を先、ドロワーの出現を後とする）。

### Requirement 6: 大規模 PDF の性能（仮想化）

**Objective:** As a 閲覧者, I want ページ数の多い PDF でも快適に操作したい, so that 大きな文書でも待たされない

#### Acceptance Criteria
1. The PDF ビューア shall 表示領域付近のページのみを描画し、画面外の遠いページは描画しない。
2. The PDF ビューア shall 全ページ分の領域を事前に確保し、スクロールバーが総量を正しく反映するようにする。
3. When ユーザーが新たな領域へスクロールする, the PDF ビューア shall その領域に入るページを描画する。
4. While あるページが表示領域から十分に離れている, the PDF ビューア shall そのページの描画リソースを解放してよい。

### Requirement 7: ローディングとエラー状態

**Objective:** As a 閲覧者, I want 読み込み状況と失敗理由を把握したい, so that 何が起きているか分かり対処できる

#### Acceptance Criteria
1. While PDF を読み込み中である, the PDF ビューア shall 読み込み中であることを示す表示を行う。
2. Where 読み込み進捗が取得可能である, the PDF ビューア shall 読み込みの進捗を表示する。
3. If PDF ファイルが破損していて読み込めない, then the PDF ビューア shall 破損している旨のエラーメッセージを表示する。
4. If PDF がパスワード保護されていて開けない, then the PDF ビューア shall パスワード保護されている旨のメッセージを表示する。
5. While いずれの PDF も読み込まれていない初期状態である, the PDF ビューア shall ファイルを開くよう促す案内を表示する。

### Requirement 8: オーバーレイ拡張基盤（フェーズ1）

**Objective:** As a 開発者, I want 各ページに座標整合したオーバーレイの配置点を確保したい, so that 将来の注釈・領域表示をデータ移行なしに追加できる

#### Acceptance Criteria
1. The PDF ビューア shall 各ページに、キャンバス層・テキスト層と同一原点に重なるオーバーレイ層を常に配置する。
2. The PDF ビューア shall オーバーレイ層に対し、PDF 文書座標と表示座標を相互変換する手段を提供する。
3. While 表示倍率が変化する, the PDF ビューア shall オーバーレイ層の位置基準をページ画像と整合した状態に保つ。
4. The PDF ビューア shall フェーズ1ではオーバーレイ層に注釈・領域などの内容を表示しない（拡張点のみを提供する）。
